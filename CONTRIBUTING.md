# Contributing

Thank you for helping improve DevOps Compass.

## Before opening a pull request

- Keep the application dependency-free unless a strong reason is documented.
- Preserve the local-first privacy model.
- Add both English and Polish text for visible content.
- Prefer concepts and observable abilities over product-name checklists.
- Do not add fake readiness scores or claims that self-assessment certifies knowledge.
- Explain dependency changes with practical reasoning.
- Run `npm run validate`.

## Content suggestions

A useful content issue should include:

1. the affected learning unit,
2. the proposed change,
3. the practical reason,
4. an authoritative source when the claim depends on changing technology,
5. the expected effect on one or more paths.

## Code style

- Use semantic HTML.
- Keep JavaScript framework-free.
- Use accessible controls and keyboard-friendly dialogs.
- Avoid external tracking, fonts and icon services.
- Escape any text that could come from imported state.

## Pull requests

Keep changes focused. A pull request that changes the competency model should not also redesign unrelated parts of the interface.
